## 类型驱动配置与选择器

画布节点提供贴近节点的“配置”卡片作为首选编辑入口。基本设置包含没有默认值的必填目录字段及归属方适配器选择器。高级设置包含可选及带默认值的目录字段、有效默认值与覆盖值标记、恢复默认控件，以及适配器详细字段。完整检查器仍提供描述、端口、诊断和图连线。IsOS 按钮节点通过共享服务发送一次受运行修订约束的 `button_activation@v0.2` 封装；若归属方结果不确定，其事件 ID 仍可见。

归属方提供的选择器沿用与软件包选择器相同的 `(node_path, setting)` 选项组。缺少归属方选项组时，检查器显示选项不可用，并禁用保存及运行；不会退回自由文本输入。EOS 适配器族使用 `adapter.type` 选项组。MuJoCo 适配器的 `adapter.settings.device_id` 和 `adapter.settings.simulator_node` 也使用归属方选项组；其他适配器族在声明归属方选择器之前保留现有字段。已保存但不可用的值及归属方原因继续显示，供用户修复。选项预览可能过期，因此归属方在 Apply 时再次校验选中值。

注册类型提供位置、非空描述、字段与有类型端口；实例提供 ID、标签、描述、设置、包锁定和输入引用。旧包侧车若缺少 `description`，使用 IsOS 的兼容默认，并在 UI 标记为目录默认，而非编造设备描述。每个可见字段从所属契约取得标签、类型、适用单位、用途、默认值与验证帮助；必填空值和单位错误就地显示。

**目标节点信息卡。** 鼠标悬停和键盘焦点打开同一个悬停时位于指针旁、键盘聚焦时位于节点旁的非模态小卡片。它分别展示标签、类型 ID、注册类型描述与实例描述、声明端口的类型/单位帮助，以及仅在 EOS 报告活动节点状态时显示实时状态。卡片通过画布 portal 浮于其他节点上方，限制在视口内，不遮挡拖动起点或连线手柄；指针进入卡片后可继续阅读。仅在用户请求时将焦点移入内容，Escape 关闭；触屏用户可从节点信息按钮打开。缺失的旧类型描述标为兼容回退；不能为草稿节点编造实时健康。

目标设置元数据中的 selector 描述符指定 IsOS 选项来源；本次每项设置只选择一个稳定值。`POST /node-options` 接收当前草稿，响应按节点路径和设置名分组。每个选项包含稳定值、标签、描述、可用性和不可用原因。UI 可按标签、稳定值、描述搜索，支持方向键、Enter、Escape、输入搜索和屏幕阅读器结果数。图只保存稳定 ID，显示标签不进入图。包锁定、依赖设置或图草稿变化时重查；以请求代数忽略过期响应。已选 ID 消失或不可用时，表单保持它并显示警告，阻止 Apply 直到选择有效项。首批选择器是 MuJoCo 场景和设备；其他软件包资源的扩展目标见[架构](architecture_cn.md#未来目标)。任意文件路径输入不能代替经过验证的注册选项。

## 连接呈现与编辑

**已实现的连线检查器。** 当前 Graph 检查器比较来源和目标端口声明的精确类型 ID，并显示两侧 IDL，包括负载字段的 `x-unit` 单位标注。缺少目录描述符时显示元数据不可用，不将连线误标为已拒绝。执行 `Check graph` 后，编辑器把四段连线目标路径映射到 IsOS 展开的诊断指针，只把 `/inputs/<port>/<source-index>` 诊断附在对应连线上，显示代码、路径和消息；多来源输入的端口级诊断保留在完整“诊断”区域。被拒绝的连线有可见线条与无障碍文本。修改、撤销、重做或刷新草稿会清除此验证结果及路由授权，再次编辑 QoS 须先检查节点图，旧编辑请求的迟到响应会被忽略。检查器将其标为**草稿检查**，另行显示 IsOS 部署状态，并可打开 EOS 监视器查看节点实时健康；Graph 连线本身尚未显示单节点实时健康标记。连线兼容性以精确类型身份为准，UI 不转换负载单位。检查器依据 IsOS `Validate.edges` 的精确来源指针，仅为 `routed:true`、`qos_eligible:true` 且 `fixed:false` 的连线提供优先级和频率上限编辑。U03 提供独立的控制／监视／Vision／日志面板。

边是输入上的来源引用。目标可选 `priority` 为 `-20`（最高）到 `19`（最低）的整数，默认 `0`；可选 `frequency_hz` 是有限正数，缺失表示该边无上限。生产者端口的 `expected_rate_hz` 仍只是提示，不是保存的边限频。优先显示实际配置；无边限频时显示 `unlimited`，生产者提示可单独显示。只编辑选中的边，保留未知字段，本地验证即时反馈，Apply 前由 IsOS 再验证。

端口形状表示通信通道，端口颜色表示准确的负载类型；节点层/组标记和运行故障轮廓独立呈现。连线图案表达保存的频率上限；长短交替线表示无限频；实线表示上限至少 30 Hz，而非测得高频。连线颜色从红色（nice -20，最高）到蓝色（nice 19，最低）表示优先级。连线、检查器和无障碍名称都显示准确的 nice 与频率值；生产者 `expected_rate_hz` 仅为单独提示。静态拓扑端口使用虚线边框，不承载负载；IsOS 确认归属方运行时路由后才提供实时连线。

## 面板与页面类型

Home、Graph、配置属于**工作页面**：紧凑对齐、方便扫读、有界滚动、状态上下文持续可见。概览或解释性首页属于**视觉页面**，可用更宽间距和图像。两类页面共享现有 SCSS 主题 token、Island-web 的排版参考、透明或轻微半透明表面；实色填充只用于提高可读性。所有布局中的控件约为 30 px 高。全部控件有可见键盘焦点、禁用与错误状态；状态不能只靠颜色表达。

已实现的 U03 工作区面板（`control`、`monitor`、`vision`、`logs`）各自在浏览器本地存储 `{open, docked, collapsed, x, y, width, height}`，以布局版本和机器人 ID 为键。拖动/调整大小只改几何信息。按机器人和布局版本保存在本机；加载时拒绝损坏数据、限制在视口内并恢复安全默认布局。停靠不销毁面板内容和订阅。关闭 Vision 断开流，隐藏日志 Follow 暂停轮询，监视轮询有界且不活动时停止。活动修订过期或 API 失联时禁用命令，即使面板重叠也保持错误可见。焦点按最近活动面板排列；Esc 取消拖动/调整大小而不改图。窄屏强制按顺序叠放，保留关键状态和 Stop 控件。

## R07 浏览器结果状态

### 客户端与状态边界

R07 实现使用 `src/services/eos/primitive-command.ts` 和 `primitive-result.ts` 生成精确的公开发送／读取请求并解码六种状态。`PrimitiveBaseCard` 记录受管理的运行和修订，在发送前及每次读取前复查 IsOS，限制后续查询，并在 EOS 错误期间保持 IsOS Stop 与当前运行日志入口。运动卡目前仅允许 `mock-cxx` 底盘；MuJoCo 运动仍由 R06 把关。

`src/services/eos/primitive-command.ts` 发送范围限定的 `base.velocity` 命令，`src/services/eos/primitive-result.ts` 执行受保护的读取；二者沿用已验证回环地址与请求选项。发送方接收已解析的活动绑定、其唯一图连线目标、活动修订、已校验的 `body_velocity` 参数、EOS 单调时间、正序号和新命令 ID；它只生成公开 `primitive_typed` 封包，以 `TextEncoder` 计算紧凑 JSON 的 `payload_length_bytes`，拒绝不安全时钟／期限数值。它不接受自由目标或私有授权。结果客户端只接受 `{commandId, activeRevision}`，生成恰好 `op`、`command_id`、`active_revision` 三个公开键，解析六状态 `DispatchResult`，核对命令 ID，并把有界传输／所有者／协议错误映射为可辨识结果。两个客户端共用解码器，使首次发送与后续查询的状态语义相同。组件通过这些服务调用，不直接调用 `fetch`。HTTP 拒绝或 `ok:false` 响应是错误，不能强行转成命令的 `Rejected` 状态。服务超时或损坏的成功响应是不可用，不是 `OutcomeUnknown`，因为只有 EOS 能赋予命令该状态。

`src/components/isos/primitive-result-state.ts` 提供纯状态模型，由 `PrimitiveBaseCard` 使用。记录包含发送时捕获的 IsOS `runId`、`activeRevision`、活动绑定路径、生成的 `commandId`、最后一个所有者 `DispatchResult` 或 null、浏览器阶段（`sending`、`following`、`terminal`、`paused`、`unavailable`）、最后的安全错误及请求代际。只有 EOS 返回关联的 `Completed`、`Failed`、`Cancelled`、`Rejected` 或 `OutcomeUnknown`，状态才可转为 `terminal`；`InProgress` 保持 `following` 或 `paused`。状态模型区分 `Failed`、`Rejected` 与传输错误，遇到错误仍保留命令 ID，发送超时或结果不确定后也不再提交第二次 `primitive_typed`。

R07 呈现一个最小活动 base 绑定卡，显示图解析目标及四个有界 SI 字段，由操作员点击 Invoke。这张已验证的卡仍仅限模拟适配器；MuJoCo 运动继续由 R06 把关。发送前解析精确的活动图绑定与目标，检查 `saved_revision === graph.revision === active_revision`、`run_id_state:known`、`state:running`、无未保存草稿、EOS 就绪以及所有者报告的目标运动可用。卡片只捕获一次运行／修订／绑定／命令 ID，取得 EOS 单调时间，在发送前立即复查 IsOS 围栏，然后只提交一次。状态模型在每次后续读取之前、页面重新可见之后重新读取 IsOS `process-status`，比较当前 `run_id` 和修订。IsOS 状态读取失败或 `run_id_state:unavailable` 时暂停后续查询并标为不可用。运行停止、运行 ID 或修订变化时取消未完成读取，并把记录封存为旧运行／不可用。浏览器请求代际与 `AbortController` 防止选择变化、Stop、卸载或运行改变之后的迟到回复更新当前卡片。即使选中相同绑定，新命令也建立新记录。UI 从 IsOS 读取活动修订，不从草稿或命令响应推断。

结果轮询一次只读一个请求，遵循 UI 契约中的一秒初始延迟、十秒错误退避上限、六十秒／十二次上限及隐藏页暂停。达到上限时 `InProgress` 仍可见；手动刷新先重新检查 IsOS，再执行一次读取。终态停止读取。若首次发送响应丢失，UI 只能用生成的 ID 进行这种受保护的结果读取，把 `unknown command ID` 视为不透明不可用。服务层绝不重发 `primitive_typed`。Vision 仍使用独立的只读 WebSocket 和修订围栏。结果卡显示命令 ID、活动修订、绑定路径、精确所有者状态或不可用解释和最近更新时间。只有 EOS 所有者事件提供对应的有效 `correlation_id`，才可预填日志筛选；否则打开无筛选的当前运行日志。不能假设命令 ID 就是日志关联 ID，也不能用 Graph 连线动画当作运动释放证明。

后续受管理的跨所有者重放使用 IsOS master `1db1aa5`、EOS R07 `60e4c16`、IsosUI R07 `202df06`、全新家目录与单个 `mock-cxx` 底盘。验证、带修订检查的 Apply、启动、操作员点击 `base.velocity`、EOS `OutcomeUnknown` 及日志记录、IsOS Stop、重启，以及当前运行的 `Rejected` 结果读取均已观察到。首次释放结果不确定后，EOS 保留运动禁用状态；新运行中被拒绝的命令没有重发。重放发现 UI 缺陷：重启后旧运行的终态 `OutcomeUnknown` 没有旧运行标记。运行围栏修复现在同时封存终态和非终态记录，保留旧所有者状态与命令 ID，并仅在新运行围栏满足后允许新命令。挂载组件回归测试覆盖运行轮换及 Stop 时迟到的读取。此模拟重放不证明 R06 的 MuJoCo 物理停止。原始证据和可复现命令位于 EOS 检出目录中被忽略的 `data/test/20261102-r07-cross-owner-live/SUMMARY.md`；本次 UI 修复的完整检查输出位于被忽略的 `data/test/20261102-r07-ui-run-fence/`。

### 与当前工作台集成

`EosWorkbench` 每五秒刷新 IsOS 状态以显示修订警告；`PrimitiveBaseCard` 在每次结果读取前获取新状态，读取后再次核对。类型化客户端区分所有者、传输和协议错误，同时维持已验证地址、CORS 模式及无凭证策略。桥接失败时命令卡保持挂载并标记不可用；后台刷新不清除命令记录。六种状态均有中英文文本，并按情况使用 `role=status` 或 `role=alert`。`Failed`、`Rejected`、`OutcomeUnknown`、旧 ID 不透明错误及桥接离线要区分显示；不能只靠颜色。R07 卡在 Invoke 旁调用 IsOS `stopProcesses()`，独立于 EOS 桥接、图可编辑性和结果轮询。它解码类型化的 `{stopped,terminal}` 响应并显示与运行 ID 匹配的 Stop 结果；R06 拥有物理停止回执。完整活动绑定列表、类型化参数表单、信息卡和浮动面板布局已由 U04/U03 提供。

### Stop 终态显示修正

R07 实际重放发现 EOS 卡从 IsOS Stop `{stopped,terminal}` 响应中读取不存在的 `result.state`，工作台也将该响应当作 `ProcessStatus` 保存。独立的 `stopProcesses()` 服务类型消除了这两种混淆。共用的运行时解码器在显示确认前验证完整终态、固定原因代码和点击时捕获的运行 ID。Home、Graph、EOS 对等待、确认、未知、未确认及响应不可用使用相同语义。EOS 卡点击 Stop 时立即隔离未完成的结果读取；各 Stop 路径在响应后重新读取 `/runtime/process-status`，状态刷新失败也保留 Stop 结果。组件测试覆盖 EOS 离线与修订过期、迟到结果、未知及传输故障；纯测试覆盖 null、缺失、损坏和运行不匹配的终态证据。完整检查命令及输出位于被 Git 忽略的 `data/test/20261102-stop-terminal-display/`。

## P07 日志游标设计

现有 `IsosLogsPanel` 使用单个可变游标，每 1.2 秒轮询 `/logs`，遇到 `rotated` 即清空行。`LogLine` 类型仅有时间、级别、来源和消息。P07 扩展 `src/services/isos/node-graph.ts` 的服务适配器及纯面板状态规约器；React 组件不拼接日志 URL。IsOS P07 提供首事件及绑定运行的游标语义。浏览器控制台行保留在独立区域，不能按时间戳混入权威服务端流。

### 状态机

从可选当前日志响应取得 IsOS `scope:{kind:manager_session|deployment_run,run_id,active_revision}`，并带 `selection_generation`。状态还保存 `{anchor,anchor_state,query,lines,cursor,gap,follow,connection}`。停止或失败的部署、PID 丢失、活动修订清空及管理器重启都保持 IsOS 持久化的 `last_run_id` 范围；只有准入新运行才改变。P07 没有清除端点。初次或改变范围时开始新代际，取消旧请求，清空其详情行和游标，再请求 `view=current` 页面，其中锚点不受筛选影响。锚点显示于筛选器上方。锚点待定时 `event=null` 且详情 `lines=[]`；沿同一绑定游标轮询并显示等待。找到后，同一响应携带严格晚于锚点的详情行；来源／级别／节点／关联筛选仅作用于这些行。改变筛选只重置该查询的游标和详情行，不能隐藏或覆盖锚点。每个异步结果携带代际及精确选择；旧运行的迟到响应被忽略。初次分页前先读取状态，重连或范围改变后再核对；绝不从 PID 或活动修订选择日志范围。

进程状态还报告 `run_id_state:none|known|unavailable`。只有由 IsOS 持久 never-run 标记证明的 none 才允许管理器范围。若状态为 unavailable 或 `view=current` 在 `/scope` 返回 HTTP 503 `log_scope_unavailable`，保留旧行但标记过期，停止声明当前运行并显示所有者错误；待所有者恢复后重试，不能猜成管理器会话。筛选 HTTP 400 `log_node_path_invalid` 或 `log_correlation_id_invalid` 附在对应输入路径。`/query/cursor` 的游标 400 解释后只重置被拒绝的查询。警报不回显不透明令牌或筛选值。

按 IsOS 接收序号／游标顺序显示，不能按 `timestamp` 排序服务端行，也不能把浏览器行合并入运行。若 IsOS 提供事件身份，则据此去重；否则依赖不透明游标与响应边界，不能用时间戳／消息作为去重键。最多保留 1,000 行。同一时刻仅一个请求；可见且启用 Follow 时按有界间隔轮询，隐藏或暂停的面板不轮询。请求失败时保留游标与行，退避至 30 秒。恢复时先核对状态。收到 `log_cursor_expired` 或 `log_collector_gap` 时沿服务端同运行恢复令牌继续，并保留缺口横幅直至操作员确认；`log_run_changed` 则开始新范围与边界。不能盲目重置到无范围的第一页。单独的 `rotated` 标志不再静默清空行。

process-control 在 `/run_id` 返回 HTTP 500 `log_scope_publish_failed` 时，先显示类型化故障，不能声称已有子进程。失败或不确定的持久边界可能留下旧范围，也可能留下幸存的新运行；使本地请求代际失效，重读状态与 `view=current`，不能假定其中一种。新范围若在无子进程时幸存，IsOS 可能返回不可用锚点；显示丢失诊断，不虚构就绪。

UI 将事件字段作为转义文本呈现，展示来源／核心／运行／关联及保存图指针，不把指针当文件路径链接，仅复制安全 ID。行的 `role=log` 使用 `aria-live=off`；独立 `role=alert` 报告收集器错误与缺口，`aria-live=polite` 只播报一次新运行或锚点。两种语言文案区分状态、缺口和筛选后空结果。刷新后键盘焦点仍在筛选器或“跳到首事件”按钮。来源／节点／关联输入受 IsOS 契约长度约束，非法输入不会发请求。

### 工作台刷新验收修复

所选归属方目录读取可能超过工作台五秒间隔。此前每次定时器触发都会使正在进行的响应失效，导致图、状态和控件一直不显示。现在同一时间只执行一次刷新，期间的定时触发会跳过。手动 **刷新** 立即禁用 Invoke、使旧请求失效，并将重复点击合并为一次后续读取。只有图／目录／状态与 EOS 发现结果一致时，后续读取才发布；失败或修订不匹配时保持只读。新修订或运行会清除旧发现／健康数据，并重启硬件轮询，避免迟到的旧运行样本重新填入。挂载代数与最新回调引用确保卸载后的回复不会发布，父组件回调变化也不会重新启动读取。

### Q01 命令截止时间顺序

一次选定版本的首次使用重放发现：浏览器读取 EOS 单调时间后、发送四秒截止时间的类型化命令前，IsOS 的进程状态读取耗时 13.9 秒。请求到达准入时已过期，界面正确显示为不可用。发送端现先完成最后一次 IsOS 状态围栏，再读取 EOS 时间，并在单次发送前立即检查最新的本地运行／修订、绑定、编辑、Stop 和取消状态。本地状态若在等待中改变，就取消发送；过期或结果不确定的命令 ID 不会重试。所有者接口契约与延迟读取的挂载测试覆盖这一顺序。

## 图目录呈现

**U01–U04 所有者功能已合并。** IsosUI 呈现 IsOS 目录，不注册运行时节点类型，也不拥有负载字段。首次使用按 **core → layer → group → node type** 选择。类型描述说明类型用途；可编辑的实例描述说明本次配置。类型 ID、设置、端口、能力、默认值、单位、校验和兼容规则以所有者 `interfaces/` 契约为准，不在 UI 中复制。

| 层级 | UI 行为 | 所有者及示例 |
| --- | --- | --- |
| Core | 选择节点图所有者。 | IsOS 拥有已保存的部署图。 |
| Layer | 缩小核心中的领域范围。 | 注册类型声明所属层。 |
| Group | 缩小层中的类型族范围。 | 注册类型声明所属组。 |

节点检查器按 **身份与描述 → 包/版本和可用性 → 设置与选择器 → 端口与连线 → 校验 → 实时状态/日志链接** 排列。选择器保留稳定值，标签与描述只用于呈现。每条连线在应用前显示 nice 优先级和频率上限。日志链接先打开当前运行最初的就绪/故障事件，再按节点路径和关联 ID 过滤。过期修订、选择器刷新和面板持久化算法见[面板与页面类型](#面板与页面类型)。

### 所选目录兼容性

选择器使用精确的注册位置和类型身份。当选项不可用时，仍显示已保存的值，供操作员在应用前修复草稿。

如果运行请求仍在进行而首次停止发生传输故障，协调器仍会等待该运行请求并再发送一次最终停止。最终停止失败时，即使运行 ID 改变，工作区停止隔离也会保持，直到显式停止获得确认。对没有待完成运行请求的未知停止结果，界面不会自动重试。
