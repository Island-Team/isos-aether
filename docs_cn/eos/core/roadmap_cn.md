## 目标架构（尚未实现）

**目标设计——尚未实现。** EOS 应成为适用于多种机器人实体的 HAL 式物理基础：类型化感知与执行、可追溯语义感知、持久物理证据、有界数据集导出、设备恢复以及可独立执行的紧急停止。它向 EI 提供稳定能力，同时将学习式任务意义与规划留在硬件安全环之外。

公开 v2 节点 API 及实体 ROS 2 或厂商适配器需要独立接口契约和资格验证。可定位夹爪需要明确目标契约。预留的 `world.snapshot` 模式可供未来融合生产者使用；当前运行时不发布该资源。

### 跨后端图执行

**目标设计——部分已实现。** EOS 使用一个受运行身份约束的执行计划，在模拟机械臂工作进程与贡献的原生节点之间传递类型化观测和软件节点连线。图格式 `0.2.1`、原有节点和端口身份、现有 Dispatcher 执行器路径保持不变。本阶段不准入任意跨软件包执行器命令，也不替换模拟机械臂安全链。当前的[设置模式守卫](../../../crates/aether-system/src/bin/aether_profile/setup.rs)允许完整且路线受支持的演示与原生节点混合图。IsOS 支持多个已选 v2 软件包服务，并通过按节点索引的 `endpoints.package_services` 交接；独立的旧版 v1 EOS 进程节点交接仍限一个进程。v2 服务 ABI 没有类型化输入回调，因此 v2 服务可以为 v1 软件消费者提供观测，但本阶段不能消费软件连线。

已实现的所有者在 Run 时从运行身份和软件包实例推导每个已选 v2 服务交接的代次，并核对所选设备的 IsOS 分帧健康响应。Status 和健康检查在合计 500 毫秒期限内重复探测，并对共用服务设备的节点去重；服务丢失或观测路线失败会将就绪状态锁定为失败，直至 Stop。所有者通过私有工作进程适配器使用已选服务 socket，不把 IsOS 服务进程当作自己的子进程监管。

设置时，EOS 从已验证的 EOS 投影和获准的 `port_routes` 编译绑定已保存修订版的候选路线计划；Run 从已验证字节重新编译，并绑定获准的运行 ID。按注册实现及已选且验证的软件包，每个节点恰好分配给一个工作进程；每条交付边保留图中精确的源节点/端口 → 目标节点/端口。路线记录标识源与目标工作进程、注册数据类型、数据类别、传输及有界交付策略。工作进程只能发布已声明输出；归属服务验证其信封，只投递到已声明输入。工作进程不得添加边、凭相似类型名称推断路线、修改已应用图或绕过 Dispatcher 写入执行器。现有 EOS [边契约](../interfaces/node/hardware/mock_cn.md#hardware_mock_cn--arm)与[节点贡献契约](../../isos/interfaces/server/eos_cn.md#node_contributions_cn)仍是当前注册的权威依据；实施阶段须先扩展所属接口，才可变更线上的字段。

设置验证检查静态软件包引用、实现可用性、精确类型 ID 与端口传输、受支持的桥接适配器、完整的演示安全链，以及是否存在第二条执行器路径；它在 Apply 前返回定位到边或节点的诊断。Run 从已保存修订版和重新验证的软件包字节编译相同路线，再于 EOS 就绪前检查具体的运行约束服务端点、套接字路径、代次、健康及运行身份。绝不静默丢弃不支持的连接。已注册来源输出的 `frequency_hz` 声明其生产频率。目标输入可请求 `desired_rate_hz` 范围；EOS 从最大值推导边 `frequency_hz` 上限，并拒绝图作者直接设置边频率。适用时，已准入边的 `priority` 与推导上限使用现有[有界调度器](dispatcher/scheduler_cn.md)；跨工作进程交付还需明确逐路线及总体字节上限、有限队列深度、取消期限，以及可观察的丢失或反压计数。观测或软件节点过载不得阻塞命令准入或 Stop。

一个持久 EOS 归属服务持有计划与运行围栏，监管其直接的模拟和原生工作进程，并在这些工作进程及已选服务之间路由类型化观测与软件输出。IsOS 监管 `endpoints.package_services` 后的 v2 软件包服务子进程；EOS 接收现有按节点索引、受运行约束的端点，不将服务进程当作直接子进程。[IsOS 服务设计](../../isos/core/service_cn.md)与 EOS [节点贡献契约](../../isos/interfaces/server/eos_cn.md#node_contributions_cn)描述当前交接。旧版 v1 EOS 进程节点子进程仍通过现有单进程归属路径运行；本目标不扩展该路径或其[软件包进程契约](../../isos/interfaces/server/eos_cn.md#package_process_cn)。

工作进程交换的每个输入/输出信封必须绑定运行 ID、已保存修订版、规范节点路径、端口、精确注册数据类型及有界负载。归属服务在入队前拒绝过期或外来发布，并在运行结束时围栏队列及正在交付的工作。本地进程内交付只有经过相同身份及类型检查，才可免于序列化。软件包服务端点仅当其注册生命周期及路线适配器明确支持对应方向时，才能成为来源或目标；端点存在本身不授予图路线。实施阶段必须在 EOS 接口中记录最终私有交换字段与错误码，同时保持归属服务 API 信封和图格式不变。

就绪要求每个已选 EOS 工作进程和子进程证明精确运行身份与修订版，并通过健康探测；必需的软件包服务端点须匹配 IsOS 受运行身份约束的服务收据，并通过健康检查。部分启动失败回滚新运行，不能替换健康的旧运行。必需的生产者、消费者、工作进程或服务丢失时，使依赖路线降级并抑制受影响命令；不得伪造成功或静默重放结果不确定的命令。Stop 首先封闭图和命令准入，经 Dispatcher 停止已准入执行器并记录受运行身份约束的适配器证明，然后取消有界观测/软件交付，最后停止并回收 EOS 所属工作进程及任何旧版进程子节点。随后 IsOS 终止并回收其 v2 软件包服务子进程，检查其退出。只有自身执行器及直接子进程的证明完整，EOS 归属服务才报告已确认 Stop；只有 EOS Stop 证明与 IsOS 自己的服务子进程退出检查一致，IsOS 才报告整体运行已停止。不确定证明保持可见且允许重试。

验收覆盖纯演示和纯软件包图的回归、模拟机械臂加摄像头/视觉的混合图，以及已选 v2 服务生产者向独立固定版本的 v1 软件消费者软件包传递观测/软件连接。v2 消费者需要后续版本提供类型化输入 ABI。单元和集成用例拒绝错误类型或传输、缺失实现、未声明边、过期运行或修订版、不安全命令路线、软件包字节变化、队列饱和、就绪失败、工作进程或服务丢失，以及不完整 Stop 证明。真实边界重放须展示 setup → Apply → readiness → control and observation → logs → Stop，包含受运行身份约束的诊断，并且没有第二次执行器释放。

### HAL 与设备生命周期

注册适配器配置声明设备身份、实体、坐标系、单位、校准与固件版本、能力、时序、限制、健康探测、物理写入边界 Stop 和恢复流程。仿真或实体驱动实现相同的类型化端口行为，同时具有明确的来源类别。EOS 仅绑定 IsOS 已验证资源，并重新验证自身投影。后端提供采样并执行获准命令；它不能创建路线、修改图设置或声称配置中不存在的能力。Dispatcher 始终是唯一执行器准入路径，实体控制器还保留独立看门狗和停止锁存。

把热路径采样与控制同较慢的感知和持久化分开。每个采样都携带来源、设备时间、主机单调时间、序号、坐标系、校准版本、质量和有界年龄。无效或过期采样使相应节点及依赖能力降级。恢复需要新鲜探测和明确状态转换；传感器丢失不能悄悄复用最后一次有效值。硬件重连绝不重复结果不确定的命令。

### 感知目录与语义证据

发布观测生产者及语义输出目录：物体或人员检测、接触开始、打滑证据、阻挡、关节极限、运动完成和健康状态。每项注明生产者、模型或规则版本、支持的坐标系、频率、不确定度、保留策略及允许的消费者。语义事件回指有界来源证据；证据不足时注明原因未知。EOS 负责物理信号解释及来源；EI 决定这些事件对任务的意义。原始媒体或嵌入留在受管读取边界后面，不塞入所有事件或日志。需要世界融合时，应声明时间和来源假设，发布新的派生资源，而非覆盖检测记录。

### 记忆写入与数据集生成

EOS 写入仅追加、受运行身份约束的物理回合：采样状态引用、获准提案及已执行命令 ID、接触和安全干预、设备故障、终态结果、时钟对齐、校准及适配器版本。物理证据库不同于 EI 认知记忆和 IsOS 部署日志。写入采用有界队列及明确的丢失或反压策略，不能阻塞伺服或 Stop 路径。Stop 刷新可证明已写入的数据，并标记缺口或不确定结果；重启不能编造缺失采样。

数据集导出器选择已获许可或其他授权的回合，解析证据引用，检查模式及时间对齐，并记录含来源摘要、标签来源、数据划分和转换版本的清单。保留失败和中断尝试。仿真特权真值可用于训练标签及评分，但绝不能成为推理输入或未标明的实体观测。仿真和实体结果分别报告，并记录教师时间、人工修正、模型调用和计算量，使学习主张可审计。

### 安全、e-stop 与恢复

采用分层准入：设置时检查配置与图，命令时检查健康及新鲜度，Dispatcher 锁存紧急停止，每个实体适配器独立执行停止和看门狗。e-stop 抢占队列及学习技能，持久展示原因，并阻止新命令。复位需要操作员授权流程、移除物理原因、新鲜探测及重新验证限制；模型不能清除锁存。遇到适配器或工作进程丢失、期限超时、传感器分歧或执行释放后结果不确定时，保持或停止受影响执行器，并暴露精确降级状态。实体切换前须逐设备测量停止延迟和看门狗到期；模拟证明不足以替代。

### 方法与验收门禁

1. 在 EOS 接口下定义类型化 HAL 配置和语义观测契约；实体适配器准入前测试单位错误、过期帧、不支持的能力及校准不匹配的拒绝行为。
2. 经 Dispatcher 和证据库重放一个仿真回合，包含故障、Stop、重启和数据集导出；验证准确命令及采样来源和显式缺口。
3. 在噪声、延迟、遮挡及传感器缺失下，用审计标签比较语义检测器；报告误报、漏报、延迟和不确定度，不将模型输出当作真值。
4. 以实体测得停止延迟、独立看门狗、阻塞写入、故障恢复及复位测试验证实体适配器；用与仿真相同的类型化端口重跑 setup → Apply → readiness → control → logs → Stop。



### 早期服务与资源目标

- **Primitive 调用:** 早期原语目录及载荷示例属于目标设计。当前图通过 EOS 所有者和分发器准入 `button_activation@v0.2` 与 `arm_joint_delta@v0.2`。当前已实现契约参见[机械臂控制](../interfaces_cn.md#arm_control_cn)、[机械臂监测](../interfaces_cn.md#arm_monitor_cn)和[所有者生命周期](../../isos/interfaces/server/eos_cn.md#owner_health_cn)。未来方向见[EOS 架构](roadmap_cn.md#目标架构尚未实现)。
- **本体发现:** 早期通用设备发现模型属于目标设计。当前模拟机械臂公开已声明的图节点、六个关节位置、健康状态和只读观测。当前已实现契约参见[机械臂控制](../interfaces_cn.md#arm_control_cn)、[机械臂监测](../interfaces_cn.md#arm_monitor_cn)和[所有者生命周期](../../isos/interfaces/server/eos_cn.md#owner_health_cn)。未来方向见[EOS 架构](roadmap_cn.md#目标架构尚未实现)。
- **能力服务:** 早期公开原生 gRPC 能力目录属于目标设计。当前图只准入已声明的按钮、模拟机械臂和监测路线。当前已实现契约参见[机械臂控制](../interfaces_cn.md#arm_control_cn)、[机械臂监测](../interfaces_cn.md#arm_monitor_cn)和[所有者生命周期](../../isos/interfaces/server/eos_cn.md#owner_health_cn)。未来方向见[EOS 架构](roadmap_cn.md#目标架构尚未实现)。
- **技能服务:** 早期公开技能服务属于目标设计。当前 EOS 演示技能是声明图路线上的进程内数据传递节点。当前已实现契约参见[机械臂控制](../interfaces_cn.md#arm_control_cn)、[机械臂监测](../interfaces_cn.md#arm_monitor_cn)和[所有者生命周期](../../isos/interfaces/server/eos_cn.md#owner_health_cn)。未来方向见[EOS 架构](roadmap_cn.md#目标架构尚未实现)。
- **世界资源:** 早期世界资源和融合 schema 属于目标设计。当前图不发布世界资源；只读回传载荷为 `arm_monitor_state@v0.2`。当前已实现契约参见[机械臂控制](../interfaces_cn.md#arm_control_cn)、[机械臂监测](../interfaces_cn.md#arm_monitor_cn)和[所有者生命周期](../../isos/interfaces/server/eos_cn.md#owner_health_cn)。未来方向见[EOS 架构](roadmap_cn.md#目标架构尚未实现)。
