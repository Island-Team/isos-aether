# EOS 硬件运行时设计

[English](../../../../docs/eos/design/runtime/hardware.md) · [硬件契约](../../interfaces/hardware_cn.md) · [Dispatcher](dispatcher_cn.md) · [MuJoCo](../../interfaces/mujoco_cn.md)

## 所有权与数据流

IsOS 管理保存的图修订、已验证的软件包资源及 Apply。当前 `0.2.0` 图包含独立的 `isos`、`ei` 和 `eos` core。EOS 只读取自己的投影，并在每次工作进程运行时创建一次声明的 `eos.hardware.mock.arm@v0.2` 适配器。旧 `isos.eos_hardware.*@v0.2` 软件包路径属于单独的兼容设计。注册类型决定位置、设置、端口、能力和生命周期；实例提供身份和值。EOS 管理实时状态与健康，Dispatcher 管理命令准入和安全。

旧 Rust HAL 传递类型化相机、底盘和机械臂样本及命令。活动 CXX mock 验证硬件边界。软件包适配器经带版本的 C ABI 进入：IsOS 验证库与 sidecar；EOS 为每个选定节点启动隔离的适配器宿主，在创建设备前复查摘要及 ABI。MuJoCo 是独立的已验证进程：EOS 将其作为直接子进程监督，将声明的适配器连接到所有者专用 Unix 套接字，不修改图。

## 准入与故障

EOS 在就绪前校验节点位置、适配器族、设置、图引用、类型化边、健康时序、坐标系 ID、运动模式与界限。畸形或过期样本仅降级所属节点。后端不能创建第二条执行器路线。所有运动携带活动修订、绑定、类型化载荷、期限与持久命令 ID 经 Dispatcher 准入。

Stop 关闭运动准入，请求已准入执行器停止，记录确认或未知结果，再终止并回收仿真器子进程。适配器或子进程丢失会降级依赖节点并禁止运动。实体适配器须执行写入边界停止及看门狗行为；mock 测试不能替代硬件资格验证。

## 后端选择

当前 Rust 运行时准入 CXX mock 硬件适配器与已验证的 MuJoCo v2 软件包适配器。IsOS 安装或链接软件包，在图格式 `0.2.0` 中选定场景和节点，验证可执行文件及资源，然后启动 EOS。EOS 只读已应用图，直接监督 MuJoCo 子进程，并仅将声明的相机、底盘和机械臂适配器连接到所有者专用 Unix 套接字。

注册节点类型决定位置、能力、设置、端口及生命周期；实例提供身份和选定值。IsOS 在 Apply 前检查精确软件包固定版本与类型化边；EOS 在就绪前检查适配器设置与健康。Dispatcher 准入所有执行器命令，并负责安全与 Stop。设置 → Apply → 就绪 → 控制 → 日志 → Stop 的流程见 [MuJoCo 首次使用](../process/mujoco-operations_cn.md)。

当前演示图使用已注册的 EOS 模拟机械臂适配器和[激活契约](../../interfaces/arm-control_cn.md)。六关节状态只属于当前工作进程运行；Dispatcher 在更新前准入技能产生的增量。

所有者将只读 `ArmObserver` 实例绑定到图中零输入的硬件层观测源路径，并将该路径传给工作进程。Monitor 请求经该实例读取唯一模拟机械臂适配器的采样器，再将[类型化机械臂观测](../../interfaces/arm-monitor_cn.md)送入声明的监控调度器、状态技能和接口出口节点。工作进程默认以 100 Hz 采样，并在每次准入运动后立即采样。图可通过模拟机械臂的高级设置覆盖 10 ms 采样间隔及 50 ms 新鲜度阈值。每个观测携带观测源路径、运行隔离、单调采样时间、序号、按图排列的关节名称和状态。所有者通过只读私有路由公开最新样本；样本过期或无效时阻止新运动，直到有效样本恢复就绪。

## 异步演示执行与监控

EOS 工作进程在按运行 ID 命名的日志中同步记录命令保留后返回接收回执。单一执行线程按序执行已接收命令；结果查询使用事件 ID 取得当前或最终结果。重复事件 ID 不会产生第二次运动。Stop 关闭新准入并等待执行线程退出；进程丢失后的未确认结果保持不确定，不自动重放。机械臂采样线程独立维护最新观测及序号，多个读取者只读取该快照，不驱动采样。详细字段见[机械臂控制契约](../../interfaces/arm-control_cn.md)。
