# v2 分发树

[English](../../../../docs/eos/design/runtime/dispatcher.md) · [硬件设计](hardware_cn.md) · [字段接口](../../interfaces/hardware_cn.md)

## 地址与职责


分发层是独立于 HAL 的 Rust 模块。发现操作读取由已校验节点 profile 构成的注册表快照；运动请求指定一个节点和一个类型化模式。分发层只解析该节点一次，并在交给适配器前检查 profile 声明的能力、实测健康、所需样本新鲜度、命令期限、数值限值及安全状态。适配器是物理操作的最后把关者。导航规划、轨迹生成和逆运动学不在该层。

软件包贡献的[节点类型](../../interfaces/node-contributions_cn.md)沿用同一分发器边和准入规则。`mujoco` 等 group 名用于位置和显示，硬件种类由注册类型提供。仅有软件包安全声明不能授予执行器路径；还必须存在已编译的适配器与停止实现。

## 命令生命周期

每个命令具有调用方提供的 `command_id` 和单调时钟期限。`Dispatcher::new_durable` 独占打开有界日志目录，在调用适配器前先同步写入带版本的预留记录，再写入 `releasing` 记录。重复 ID 返回已保存结果；相同 ID 对应不同命令时拒绝。重启后，未完成记录转为 `outcome_unknown`，绝不自动再次下发。损坏或过大的记录阻止启动。内存构造函数只用于测试与进程内原型；受管 Rust 运行时使用持久构造函数。释放前日志写入失败则拒绝命令；释放后终态写入失败则保留不确定结果。

急停先锁存进程安全状态，再调用各执行器独立的停止方法。分发层不再跨可能阻塞的适配器调用持有释放锁。适配器必须在物理写入边界锁存停止，使延迟的提交无法在停止后重新执行；CXX mock 实现并测试了该规则。mock 测试证明提交阻塞时停止仍能返回，但真实控制器的停止延迟与独立速度看门狗仍须在切换前测量。读取或样本校验失败会使该节点的 Rust 健康状态降级；只有 `refresh_node` 的有效且新鲜的探测才能清除故障。健康、安全和物理停止错误分别可见。

## 与现有运行时的关系和验证


用假 HAL 注册表测试精确路径解析、接口发现和节点隔离。集成测试覆盖正常运动、过期观测、限值、过期命令、跨重启重复 ID 重放、损坏日志拒绝、健康降级与恢复、释放前取消以及 mock 释放阻塞时的急停。真实硬件停止延迟、控制器执行的速度租约到期和部署中的 ROS 2 图仍是正式切换前的验收用例。可复现命令写入[开发指南](hardware-guide_cn.md)，完整输出放在 `data/test/<run-id>/`。

按钮演示通过内置 `arm.delta` 原语准入 `arm_joint_delta@v0.2`。在模拟适配器更新状态之前，调度器拒绝单关节超过 0.25 rad 的增量，或让结果关节超出 ±3.14 rad 的命令。见[机械臂控制](../../interfaces/arm-control_cn.md)。

演示监控返回路径独立于命令响应检查最新六关节观测。样本超过配置阈值（默认 50 ms）、关节为非有限数或位置超过配置限值时撤销运动就绪状态。100 Hz 采样器可在取得新的有效样本后恢复就绪。[私有监控读取](../../interfaces/arm-monitor_cn.md)保持只读，不能绕过 Dispatcher 准入。
