# 编写和验证节点

[English](../../../../docs/isos/interfaces/node/authoring.md) · [配置形态](profile_cn.md) · [类型](type_cn.md)

从[当前演示图](../../../../config/graph-pool/demo.nodes.json)开始。图格式 `0.2.0` 恰好要求 `isos`、`ei`、`eos` 三个核心。每个注册 ID 遵循 `<core>.<layer>.<group>.<type>@v0.2`，实例须置于相同的核心、层和组。演示图包含 16 个注册节点实例：八个用于控制，八个用于观测。

1. 先实现并测试 EI 或 EOS 归属方接口和生命周期，再注册包装节点。包装声明接口在图中的位置，不重复归属方逻辑。
2. 在归属核心中注册类型。只有已实现图交付路由时才添加端口；仅报告健康的配置无需端口。
3. 添加映射键与 `id` 一致的实例，仅使用允许的设置及适用的必需输入引用。路径采用 `<core>/<layer>/<group>/<id>`。
4. 针对保存的修订验证并 Apply 图。Run 启动 EI 与 EOS 归属方进程，随后检查各进程健康，并显式 Stop 部署。

演示图声明类型化控制与观测连接。激活事件经 EI 到达 EOS；EOS 将其转换为有界的六关节增量并传给模拟适配器。同一适配器的观测状态经 EOS 和 EI 异步返回 UI 监控节点。未知类型、错误位置、缺少必需输入和不兼容端口均会导致准入失败。模拟适配器没有实体执行器路由。
