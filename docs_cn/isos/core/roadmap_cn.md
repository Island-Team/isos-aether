## 目标架构（尚未实现）

**目标设计——尚未实现。** 目标是可移植的节点运行时：允许第三方贡献能力，同时保持控制权清晰，并保留足够证据以重放和诊断实验。每次运行使用声明式、不可变的图快照。注册类型提供归属核心、实现身份、精确版本、端口、设置模式、能力要求、资源限制和生命周期。实例选择数值与连接；归属运行状态、健康和测量数据留在图字节之外。任何软件包或后端都不能绕过 EOS Dispatcher 声明第二条执行器路径。

### 从图到执行的统一类型化计划

将已验证图及软件包锁定编译为一份运行计划：节点实现和资源摘要、归属投影、端口绑定、桥接路线、启动依赖、就绪检查和逆序 Stop。Apply 将计划绑定到精确图修订。Run 和 Restart 在启动前重新检查输入；软件包、资源或归属能力变化时须重新 Apply。归属方证明哪些已声明实例就绪；故障指出节点及计划阶段。未来的图编辑创建新修订并受控替换，不会原地修改运行中的归属投影。

让全部 16 个内置演示实例与软件包节点经过相同的注册实现路径。将外部 UI 节点绑定到已验证的展示描述符，指明准确输出端口、载荷类型、运行及修订。描述符仅授予展示权限；UI 失焦、断线或控制租约过期仍须关闭命令准入，并单独验证恢复。

每条实时连接都采用类型化路线和交付策略。命令需要有界队列、期限、持久事件身份、终态查询；无法证明是否已释放执行时须明确标记 `outcome_unknown`。高频观测采用有界最新值或采样交付，并带序号和采样年龄；EI 或 UI 消费者变慢不能阻塞 EOS 本地安全检查。跨核心交付前，两端归属方都须确认路线、运行 ID、修订、载荷类型和传输方式。缺失实现时拒绝 Run，不静默丢值。反馈环须在准入前具有显式延迟／状态节点和有界迭代策略。

### 可移植性与开放软件包生态

通过主机适配层封装进程启动、IPC、路径、时钟和信号，并保持相同的归属生命周期语义。Unix socket 是当前本地传输；其他平台适配器必须证明等效的私有端点访问、取消、子进程监管、崩溃恢复和 Stop，才能声明支持。软件包作者发布类型化贡献及不可变资源摘要；IsOS 解析精确锁定和可信策略元数据，各归属方重新验证自己的载荷与能力语义。签名且会过期的注册表元数据、撤销和明确离线策略是未来信任门禁，不是当前软件包行为。图、节点、软件包和传输契约分别版本化，以便生态参与者明确升级边界。

### 可追踪性、实验与仿真到实体迁移

为每次运行分配图修订、计划摘要、软件包与资源摘要、归属代数和追踪 ID。沿获准路线传递节点路径、端口、事件 ID、因果父项、单调采样时间和来源序号。将验证、Apply、就绪、准入、结果、降级、恢复和 Stop 记录为有界结构化事件。调试工具应重建因果路径，并区分执行前拒绝与释放后结果不确定；不得记录原始媒体、提示词、秘密或无限制载荷。

仿真和实体适配器使用相同的类型化图端口及 EOS Dispatcher 契约。实体配置将设备身份、坐标系、校准版本、时序、限制和可用传感器绑定到一次运行；切换配置需要重新验证和 Apply，不能悄悄替换后端。仿真可以提供用于评分的额外真值，但不能让该真值进入部署推理路线。保留重放输入和来源，使失败仿真回合能够在相同任务和风险预算下与受监督实体试验比较。实体切换还须测量停止延迟、看门狗、传感器新鲜度和恢复；仿真成功本身不足以证明可上线。

### 方法与验收门禁

1. 在所属接口中定义一份类型化运行计划模式，先验证图、软件包、资源和归属能力拒绝，再改动执行器。
2. 在每个归属方运行一个第三方节点和一条跨核心类型化路线，完成 setup → Apply → readiness → control → logs → Stop；检查重复事件、旧运行、缺失桥接、消费者阻塞、工作进程丢失和结果不确定。
3. 用计划和追踪重放固定仿真回合，再在监督下绑定实体配置；比较等价观测与命令结果，不让仿真专属标签进入推理。
4. 用同一套生命周期和 Stop 用例验证每种主机适配器；仅公布已测试的主机与设备组合。
