## IsosUI 文档

[English](../../../../docs/isos/core/ui/webui.md) · [文档](../../../README_cn.md)

IsosUI 包含 IsOS 部署的浏览器工作台和终端客户端。浏览器编辑包含 `isos`、`ei`、`eos` 三个核心的 `0.2.1` 格式图，并呈现各核心声明层中的已注册节点；终端客户端呈现所有者状态和操作。IsOS 负责图持久化、软件包准入、进程状态和[面向 UI 的节点契约](../../interfaces/api/README_cn.md)。EOS 负责实时控制与观测。客户端使用这些所有者接口，不定义另一种图格式。

## 客户端配置

IsOS 从 [`config/isosui.toml`](../../../../config/isosui.toml) 读取 Web 和终端客户端默认值。`ISOSUI_CONFIG` 可指定另一个绝对路径的 TOML 文件。进程环境变量覆盖 TOML：`ISOSUI_DEFAULT_INTERFACE`（`web` 或 `tui`）、`ISOSUI_LOCALE`（`en` 或 `cn`）、`ISOSUI_STARTUP_TIMEOUT_MS`（1000–60000）及 `ISOSUI_POLL_INTERVAL_MS`（500–10000）。IsOS 校验解析后的设置，并向两个客户端提供非秘密值。持久偏好写入 TOML；临时覆盖使用环境变量。

## IsosUI 架构

[English](../../../../docs/isos/core/ui/webui.md) · [阅读地图](webui_cn.md) · [当前设计](webui_cn.md)

当前工作台呈现 IsOS `0.2.1` 节点图格式和各所有者目录。画布几何信息保存在浏览器中，图设置由 IsOS 保存，网络请求集中在 `ui/src/services/`。UI 不负责执行器准入。控制与监视界面使用两条独立的所有者路由：用户操作发送一次带运行围栏的命令，观测数据则独立采样和转发。IsOS 管理运行与修订围栏；EOS 决定是否准许运动。关闭监视面板不会停止 EOS 的本地采样。

图卡将按钮的 `activation` 输出标为 UI→EI：事件沿带运行围栏的 IsOS/EI Unix 套接字图路线传送。原语绑定卡将 UI→EOS 标为独立的 EOS Dispatcher 控制端点。直接类型化原语请求经过 EOS 回环桥接和私有所有者 IPC，不画成可执行图端口。这两个标记区分不同的准入路径，不表示按钮绕过 EI 安全路径。

## 类型驱动配置与选择器

Graph 左侧有两种图库视图。节点库根据 IsOS 目录生成可搜索的 `核心 → 层 → 组 → 节点` 树。内置节点直接显示；软件包节点显示稳定的界面颜色和精确的 `id@version` 锁定。多个软件包锁定向同一组贡献节点时，按软件包文件夹分开。软件包库读取已安装清单，包含没有节点类型的软件包，并用相同的树显示每个包的目录贡献。选择软件包后，右侧显示安装凭据和现有配置表单。检查器使用独立于图库视图的明确选择目标。显示其他目标时，软件包配置仍保持挂载并保留草稿；草稿未保存时，切换精确软件包版本仍需确认。目标消失时，检查器显示空状态。表单的“重新加载”重读配置；图库的“刷新”重读清单和带修订保护的目录。安装和移除仍在 Home。树使用原生展开控件和可聚焦的类型按钮；窄屏依次叠放图库、画布和检查器。软件包颜色不参与节点图准入，编辑器保留精确锁定和未保存的草稿。

Graph 从这些树逐个添加软件包节点。原有的软件包节点集区域和预览控件已移除；IsOS 软件包 API 仍可供其他客户端使用。Graph 加载或刷新目录时不再请求节点集。

**移除验证（2026-11-12）。** UI 类型检查、49 个文件中的 217 项测试以及 Web 和 TUI 构建均通过。中英文链接检查覆盖 370 页，没有损坏链接；IsOS 文档检查没有发现问题。日志位于被忽略的 `data/test/20261112-remove-graph-node-sets/`。

**图库验证（2026-11-12）。** `cd ui && npm run typecheck`、`npm test`（49 个文件中的 217 项测试）及 `npm run build`（Web 和 TUI）通过。`python3 scripts/check_doc_links.py --all` 检查 370 页，没有损坏链接；`python3 crates/isos/tools/check_isos_docs.py` 没有发现中英文 IsOS 文档问题；`git diff --check` 通过。完整输出位于被忽略的 `data/test/20261112-generic-package-core-boundary/library-final-*.log`。

画布节点提供贴近节点的“配置”卡片作为首选编辑入口。基本设置包含没有默认值的必填目录字段及归属方适配器选择器。高级设置包含可选及带默认值的目录字段、有效默认值与覆盖值标记、恢复默认控件，以及适配器详细字段。完整检查器仍提供描述、端口、诊断和图连线。IsOS 按钮节点通过共享服务发送一次受运行修订约束的 `button_activation@v0.2` 封装；若归属方结果不确定，其事件 ID 仍可见。

适配器类型与设置选项来自 IsOS 对当前草稿返回的节点选项。编辑器先显示已载入目录中按精确软件包版本锁定匹配的适配器族。检查修改后的草稿时，先前的归属方选项仍可见但不可操作；只有当前草稿的成功响应才能授权这些选项并解除 Apply 和 Run 的阻塞。刷新失败时显示错误，并继续禁用旧的归属方选项。编辑器按字段名和稳定值呈现所有返回的 `adapter.settings.*` 选项组；没有归属方选项组的现有非私有设置仍作为普通字段显示。软件包适配器提供其声明的 `service_instance`；编辑器不写入私有服务 socket。它不根据适配器名称推断必填字段。Apply 时，IsOS 和 EOS 再次验证所选软件包、设置和硬件路由。


注册类型提供位置、非空描述、字段与有类型端口；实例提供 ID、标签、描述、设置、包锁定和输入引用。旧包侧车若缺少 `description`，使用 IsOS 的兼容默认，并在 UI 标记为目录默认，而非编造设备描述。每个可见字段从所属契约取得标签、类型、适用单位、用途、默认值与验证帮助；必填空值和单位错误就地显示。

**目标节点信息卡。** 鼠标悬停和键盘焦点打开同一个悬停时位于指针旁、键盘聚焦时位于节点旁的非模态小卡片。它分别展示标签、类型 ID、注册类型描述与实例描述、声明端口的类型/单位帮助，以及仅在 EOS 报告活动节点状态时显示实时状态。卡片通过画布 portal 浮于其他节点上方，限制在视口内，不遮挡拖动起点或连线手柄；指针进入卡片后可继续阅读。仅在用户请求时将焦点移入内容，Escape 关闭；触屏用户可从节点信息按钮打开。缺失的旧类型描述标为兼容回退；不能为草稿节点编造实时健康。


## 连接呈现与编辑

**连线与端口频率。** Graph 检查器比较来源和目标端口声明的精确类型 ID，并显示两侧 IDL，包括负载字段的 `x-unit` 单位标注。缺少目录描述符时显示元数据不可用。执行 `Check graph` 后，编辑器把连线目标路径映射到 IsOS 的诊断指针。被拒绝的连线有可见线条与无障碍文本。源输出的注册 `frequency_hz` 固定于节点类型；处理节点可在自身输出声明不同的预期频率。目标输入绑定可包含正数 `min` 和 `max` 的 `desired_rate_hz` 范围，节点检查器编辑该范围，连线检查器显示两端声明。

边是输入上的来源引用。可选 `priority` 为 `-20`（最高）到 `19`（最低）的整数，默认 `0`。期望频率属于目标输入端口，来源频率属于源输出端口；不再编辑边的 `frequency_hz`。省略期望范围边界表示没有请求该限制。

端口形状表示通信通道，端口颜色表示准确的负载类型；节点层/组标记和运行故障轮廓独立呈现。连线图案表达目标输入的期望最大值；没有最大值时显示无上限图案。连线颜色从红色（nice -20，最高）到蓝色（nice 19，最低）表示优先级。连线检查器显示源输出预期频率和目标输入期望范围。静态拓扑端口使用虚线边框，不承载负载。



## 面板与页面类型

Home、Graph、配置属于**工作页面**：紧凑对齐、方便扫读、有界滚动、状态上下文持续可见。概览或解释性首页属于**视觉页面**，可用更宽间距和图像。两类页面共享现有 SCSS 主题 token、Island-web 的排版参考、透明或轻微半透明表面；实色填充只用于提高可读性。所有布局中的控件约为 30 px 高。全部控件有可见键盘焦点、禁用与错误状态；状态不能只靠颜色表达。

已实现的 U03 工作区面板（`control`、`monitor`、`vision`、`logs`）各自在浏览器本地存储 `{open, docked, collapsed, x, y, width, height}`，以布局版本和机器人 ID 为键。拖动/调整大小只改几何信息。按机器人和布局版本保存在本机；加载时拒绝损坏数据、限制在视口内并恢复安全默认布局。停靠不销毁面板内容和订阅。关闭 Vision 断开流，隐藏日志 Follow 暂停轮询，监视轮询有界且不活动时停止。活动修订过期或 API 失联时禁用命令，即使面板重叠也保持错误可见。焦点按最近活动面板排列；Esc 取消拖动/调整大小而不改图。窄屏强制按顺序叠放，保留关键状态和 Stop 控件。

## R07 浏览器结果状态



`src/services/eos/primitive-command.ts` 发送范围限定的 `base.velocity` 命令，`src/services/eos/primitive-result.ts` 执行受保护的读取；二者沿用已验证回环地址与请求选项。发送方接收已解析的活动绑定、其唯一图连线目标、活动修订、已校验的 `body_velocity` 参数、EOS 单调时间、正序号和新命令 ID；它只生成公开 `primitive_typed` 封包，以 `TextEncoder` 计算紧凑 JSON 的 `payload_length_bytes`，拒绝不安全时钟／期限数值。它不接受自由目标或私有授权。结果客户端只接受 `{commandId, activeRevision}`，生成恰好 `op`、`command_id`、`active_revision` 三个公开键，解析六状态 `DispatchResult`，核对命令 ID，并把有界传输／所有者／协议错误映射为可辨识结果。两个客户端共用解码器，使首次发送与后续查询的状态语义相同。组件通过这些服务调用，不直接调用 `fetch`。HTTP 拒绝或 `ok:false` 响应是错误，不能强行转成命令的 `Rejected` 状态。服务超时或损坏的成功响应是不可用，不是 `OutcomeUnknown`，因为只有 EOS 能赋予命令该状态。

`src/components/isos/primitive-result-state.ts` 提供纯状态模型，由 `PrimitiveBaseCard` 使用。记录包含发送时捕获的 IsOS `runId`、`activeRevision`、活动绑定路径、生成的 `commandId`、最后一个所有者 `DispatchResult` 或 null、浏览器阶段（`sending`、`following`、`terminal`、`paused`、`unavailable`）、最后的安全错误及请求代际。只有 EOS 返回关联的 `Completed`、`Failed`、`Cancelled`、`Rejected` 或 `OutcomeUnknown`，状态才可转为 `terminal`；`InProgress` 保持 `following` 或 `paused`。状态模型区分 `Failed`、`Rejected` 与传输错误，遇到错误仍保留命令 ID，发送超时或结果不确定后也不再提交第二次 `primitive_typed`。


结果轮询一次只读一个请求，遵循 UI 契约中的一秒初始延迟、十秒错误退避上限、六十秒／十二次上限及隐藏页暂停。达到上限时 `InProgress` 仍可见；手动刷新先重新检查 IsOS，再执行一次读取。终态停止读取。若首次发送响应丢失，UI 只能用生成的 ID 进行这种受保护的结果读取，把 `unknown command ID` 视为不透明不可用。服务层绝不重发 `primitive_typed`。Vision 仍使用独立的只读 WebSocket 和修订围栏。结果卡显示命令 ID、活动修订、绑定路径、精确所有者状态或不可用解释和最近更新时间。只有 EOS 所有者事件提供对应的有效 `correlation_id`，才可预填日志筛选；否则打开无筛选的当前运行日志。不能假设命令 ID 就是日志关联 ID，也不能用 Graph 连线动画当作运动释放证明。



`EosWorkbench` 每五秒刷新 IsOS 状态以显示修订警告；`PrimitiveBaseCard` 在每次结果读取前获取新状态，读取后再次核对。类型化客户端区分所有者、传输和协议错误，同时维持已验证地址、CORS 模式及无凭证策略。桥接失败时命令卡保持挂载并标记不可用；后台刷新不清除命令记录。六种状态均有中英文文本，并按情况使用 `role=status` 或 `role=alert`。`Failed`、`Rejected`、`OutcomeUnknown`、旧 ID 不透明错误及桥接离线要区分显示；不能只靠颜色。R07 卡在 Invoke 旁调用 IsOS `stopProcesses()`，独立于 EOS 桥接、图可编辑性和结果轮询。它解码类型化的 `{stopped,terminal}` 响应并显示与运行 ID 匹配的 Stop 结果；R06 拥有物理停止回执。完整活动绑定列表、类型化参数表单、信息卡和浮动面板布局已由 U04/U03 提供。

### 状态机

从可选当前日志响应取得 IsOS `scope:{kind:manager_session|deployment_run,run_id,active_revision}`，并带 `selection_generation`。状态还保存 `{anchor,anchor_state,query,lines,cursor,gap,follow,connection}`。停止或失败的部署、PID 丢失、活动修订清空及管理器重启都保持 IsOS 持久化的 `last_run_id` 范围；只有准入新运行才改变。P07 没有清除端点。初次或改变范围时开始新代际，取消旧请求，清空其详情行和游标，再请求 `view=current` 页面，其中锚点不受筛选影响。锚点显示于筛选器上方。锚点待定时 `event=null` 且详情 `lines=[]`；沿同一绑定游标轮询并显示等待。找到后，同一响应携带严格晚于锚点的详情行；来源／级别／节点／关联筛选仅作用于这些行。改变筛选只重置该查询的游标和详情行，不能隐藏或覆盖锚点。每个异步结果携带代际及精确选择；旧运行的迟到响应被忽略。初次分页前先读取状态，重连或范围改变后再核对；绝不从 PID 或活动修订选择日志范围。

进程状态还报告 `run_id_state:none|known|unavailable`。只有由 IsOS 持久 never-run 标记证明的 none 才允许管理器范围。若状态为 unavailable 或 `view=current` 在 `/scope` 返回 HTTP 503 `log_scope_unavailable`，保留旧行但标记过期，停止声明当前运行并显示所有者错误；待所有者恢复后重试，不能猜成管理器会话。筛选 HTTP 400 `log_node_path_invalid` 或 `log_correlation_id_invalid` 附在对应输入路径。`/query/cursor` 的游标 400 解释后只重置被拒绝的查询。警报不回显不透明令牌或筛选值。

按 IsOS 接收序号／游标顺序显示，不能按 `timestamp` 排序服务端行，也不能把浏览器行合并入运行。若 IsOS 提供事件身份，则据此去重；否则依赖不透明游标与响应边界，不能用时间戳／消息作为去重键。最多保留 1,000 行。同一时刻仅一个请求；可见且启用 Follow 时按有界间隔轮询，隐藏或暂停的面板不轮询。请求失败时保留游标与行，依次等待 2、5、10 秒，之后最多等待 30 秒重试；页面重新可见时立即核对。恢复时先核对状态。收到 `log_cursor_expired` 或 `log_collector_gap` 时沿服务端同运行恢复令牌继续，并保留缺口横幅直至操作员确认；`log_run_changed` 则开始新范围与边界。不能盲目重置到无范围的第一页。单独的 `rotated` 标志不再静默清空行。

选择连线后点击**检查节点图**。检查器依据 IsOS 返回的精确来源指针显示路由类别。仅当 IsOS 确认连线已声明路由、允许 QoS 且不是固定连线时，才能编辑优先级。nice 优先级为 -20（最高）至 19（最低）的整数，有效权重为 `20 − 优先级`。源输出预期频率和目标输入期望范围作为端口属性显示；在目标节点检查器中编辑范围。输入后按 Enter 或离开字段提交草稿。每次编辑都会清除先前的路由授权；再次编辑 QoS 前需重新**检查节点图**。无效值阻止保存和保存并运行。Apply 前会重新请求 IsOS 检查精确草稿；拒绝或过期检查不会发送 Apply。仅设计用途与固定连线仍可查看，但不能编辑 QoS。

打开节点图，通过工作区工具栏分别显示控制、监控、视觉和日志面板。每个面板都可以停靠、浮动、收起或关闭。拖动浮动面板标题可以移动；聚焦右下角手柄后可用方向键调整大小。窄屏时面板堆叠显示。紧凑的顶部导航始终提供“停止部署”；仅在重要警告或停止请求待确认时显示第二条顶部提示。普通消息五秒后消失，并留在日志的浏览器分区。即使 EOS 离线，也可以通过 IsOS 请求停止。

通过 EI 和 EOS 页面按钮查看各自的状态及相关信息；节点图“视图”菜单也会跳转到相同页面。点击“停止部署”会立即阻止本次运行的新调用和结果跟踪；停止结果不明时，界面不会显示为停止成功。关闭或收起监控与视觉面板会暂停轮询或视频流。日志面板停靠或收起时保留本次运行的不透明游标并暂停跟踪；关闭后重新打开会重新检查 IsOS 状态与日志范围。布局按机器人保存在本机，并限制在当前视口内。参见[工作面板契约](../../interfaces/api/client_cn.md#workspace_panels)。

保存的节点图含有 `isos.ui.vision.monitor@v0.2` 时，顶部导航显示“视觉”页面。每个监视节点都有单独标记的画面。将相机输出经 `eos.interface.egress.vision_flow@v0.2` 连接到监视节点，然后应用并运行。页面从 IsOS 读取活动图的绑定，为每个监视节点分别订阅；其他运行、修订、传输节点、来源或监视节点的画面会被拒绝。图像旁显示已接受画面的实际像素尺寸、相机来源、编码及接收帧率。“收到的画面”表示流中的像素尺寸，可能与软件包设置或屏幕上的显示尺寸不同；页面不会用不同计时基准的来源时间戳推断延迟。离开页面、编辑节点图、停止运行或连接断开时，画面详情会清除。

所选节点图与目录快照的修订一致后，节点图可以先显示；进程状态或就绪状态仍可能在加载。点击**重新载入已保存节点图**会请求新快照；响应通过修订检查之前，原画布继续显示。从外部 CLI 安装软件包后，返回 Graph 页面会刷新软件包类型和已安装清单，同时保留未保存的图编辑。外部修改节点图后，点击**刷新**以重新加载完整的所有者视图。参见[节点图加载契约](../../interfaces/api/client_cn.md#graph_loading)。

输入端口位于节点边框内，端口标签避开连接点；输出端口位于边框外。选中节点后按 **R** 可交换输入与输出所在侧，标签和已连接连线的端点会随之移动。此操作只改变画布布局，不修改节点图连接。

## 软件包配置与硬件目录

在 Home 中，选择已安装软件包精确版本旁的**配置**。IsOS 提供已验证的中英文字段描述和当前本地配置修订。表单编辑类型化字段；**原始 TOML** 从已保存文档开始。保存前先验证。保存时提交所读取的修订；并发修改后须重新加载。配置仅属于部署和精确版本；保存不会改变正在运行的实例。所选服务输入变化后，运行前须重新 Apply。

在 Graph 中，用图库左侧的两个图标切换**节点库**和**软件包库**。节点库是可搜索的“核心 → 层 → 组 → 节点”树。内置类型直接显示；软件包类型带有稳定的软件包颜色和精确版本标记。同一组有多个软件包贡献时，该组出现软件包文件夹。软件包库列出所有已安装的精确版本，包括没有节点的版本；展开后仅浏览该软件包的“核心 → 层 → 组 → 节点”贡献。选择软件包后，右侧显示其收据和配置。右侧检查器跟随选中的软件包、目录类型、画布节点、连线或节点组，与左侧图库视图无关。切换图库视图不会改变检查器；选择其他对象会立即显示其详情。返回原软件包时未保存的配置仍在；切换到其他软件包前会询问是否放弃修改。刷新重新读取软件包清单与目录；配置中的重新加载读取已保存配置。从软件包添加的节点保留精确版本锁定。旧版软件包进程节点不出现在新建节点目录中；已有锁定版本的图仍可读取。画布快捷添加菜单也显示精确软件包版本。IsOS 仅在 Run 时启动所选服务。

内置 mock-arm 演示只能作为完整链运行。先用**新建软件包图**建立空白草稿，逐个加入软件包硬件节点，并另存为独立图库文件。

对于 `0.2.1` 服务软件包，先在 IsOS 中检查精确发行版并批准下载。在 Home 配置已安装的精确版本，再在 Graph 中添加所需的软件包节点。检查图、保存并 Apply，然后 Run。EOS 显示每个选定设备的健康状态；在活动绑定卡发送一次有界命令并查看关联结果。读取当前运行日志并通过 IsOS Stop。本地源码维护者可在 `pkg release --checked` 前使用 `isos pkg check --source <绝对源码路径> --version 0.2.1 --output <空的绝对目录> --package-config <绝对package.toml> --graph <绝对native-graph.json> --graph <绝对robocasa-graph.json>` 重放两个预设。

鼠标在 Graph 节点上稍作停留、键盘聚焦或轻触信息按钮，即可查看独立的目录类型与实例描述、类型化端口以及 EOS 所有者报告的健康状态。Escape 或关闭按钮退出视口内的信息卡。在 EOS 中，每个受支持的活动 `@v0.2` 底盘或机械臂绑定都有独立控制卡。检查图解析的唯一目标、原语、单位和限值；更改目标须编辑并 Apply 节点图。等待已知 IsOS 运行、相等的保存／活动修订及 EOS 就绪健康状态。仅点击一次调用。浏览器显示发送中时保留命令 ID，随后显示 EOS 的精确状态。`InProgress` 仅用同一 ID 经授权的公开结果读取跟进；丢失响应绝不重新提交。EOS 控制失败时仍可通过 IsOS 停止部署。参见 [U04 契约](../../interfaces/api/client_cn.md#control)。

“检查节点图”将缺少的必需输入显示为警告，并列出节点与输入路径。仍可保存和 Apply；Run 期间断开的路径不传递数据。修复连接并再次 Apply 后，该路径才可运行。
